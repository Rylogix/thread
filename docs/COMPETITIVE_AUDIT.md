# THREAD challenge gap analysis

Audit date: August 27, 2026

## Baseline

THREAD already has a coherent shared planning surface: an editable dependency graph, CPM and conflict analysis, reproducible Monte Carlo simulation, scenarios, D1/local persistence, an activity stream, 38 strict WebMCP tools, a debugger, and a no-login seed. The baseline passed TypeScript, 20 unit/integration tests, production build, three browser journeys, Worker startup validation, and the deployed D1 round trip.

The live review found good visual hierarchy and graph readability, but the product story still reads as “agent-editable planning dashboard.” The agent can mutate shared reality directly, scenarios are passive snapshots, activity is too terse for provenance, and the 71% → 90% optimization is difficult to understand or trust within seconds.

## Competition and originality

The [official challenge](https://webmcp.devpost.com/) weights WebMCP leverage, execution, impact, and creativity equally and asks for experiences that become meaningfully better when people and agents use them together. The [official rules](https://webmcp.devpost.com/rules) require a working URL, public licensed repository, English explanation, and public YouTube demo under three minutes.

The visible [OpenAI WebMCP showcase](https://developers.openai.com/showcase) is dominated by agents manipulating the same artifact as a human. The nearest planning examples are WanderNote and Sunday Table; Margin Editor adds separate agent identity. Their published descriptions do not foreground competing executable proposals, locked human constraints, deterministic simulation evidence, approval-gated application, or reversible provenance. The Devpost entrant gallery was not yet published during this audit.

Safe originality statement:

> Unlike the visible showcase examples, which primarily let an agent manipulate a shared artifact, THREAD makes the negotiation itself inspectable: constraints, structured operations, simulation evidence, graph diffs, approval, provenance, and rollback are first-class product objects.

## Gaps by judging criterion

| Criterion | Current strength | Highest-value gap |
|---|---|---|
| WebMCP leverage | Broad, strict tool surface over real shared state | Tools need a meaningful multi-step protocol with agent proposals and human authority, not more direct CRUD |
| Execution | Stable graph, engines, persistence, fallback, debugger | No single 60–90 second workflow explains the product or makes approval safety obvious |
| Potential impact | Real constraint-aware execution problem | Trust and accountability are weak when agents mutate the live plan directly |
| Creativity and ambition | Simulation-backed dependency planning | Scenarios are not yet an agent-human negotiation system with evidence and consent |

## Selected P0 implementation

Build a Decision Room as a complete state machine:

`draft → awaiting decision / revised → approved or rejected → applied → rolled back`

The human locks guardrails. The agent can inspect context, create deterministic safest/fastest/highest-impact proposals, compare evidence, revise a proposal, and ask a structured question. It cannot approve. The human compares graph diffs and simulations, answers any tradeoff, explicitly applies one proposal atomically, inspects the decision ledger, and can roll it back.

Every proposal must be generated by the shared deterministic services and carry exact operations, per-operation reasons, before/after critical path and simulation metrics, constraint checks, graph diffs, upside, tradeoffs, seed, and iteration count. Existing graph, simulation, scenarios, tools, and persistence remain intact.

## P0 acceptance signals

- The seeded 71.4% baseline produces three materially different, reproducible proposals.
- Locked deadline, budget, capacity, preserved WebMCP tasks, minimum probability, and maximum risk are visibly evaluated.
- No proposal changes the live plan before a human clicks Approve.
- Proposal application is one validated persisted state transition and can be rolled back.
- Agent questions use proposal-derived predicted effects; answers persist and are readable through WebMCP.
- The UI explains changed nodes, edges, critical path, feasibility, risks, costs, and reasons without requiring raw JSON.
- The debugger proves discovery, malformed-input rejection, idempotent retries, UI synchronization, approval separation, and rollback.

## Deliberate non-goals

- No built-in chatbot or external model API.
- No generic approval framework, collaboration suite, or new auth system.
- No additional planning feature unless it directly strengthens the negotiation demo.
- No unsupported originality claims.
